# claude.ai 채팅에서 학습 목표 설정

claude.ai 채팅에서 쓰는 방식이다. 위키는 GitHub 저장소에 있고, 이 채팅은 거기서 `goals/` 폴더만 읽고 목표 지도 `goals/<id>.toml`을 직접 커밋한다. 판단 기준은 같은 저장소의 `skills/wiki-goal/SKILL.md` (a)·(c)·(d)절을 따르고, 형식 예시는 `skills/wiki-goal/example.toml`이다. 그 파일의 도구 실행(`list`, `suggest` 등)과 (f)·(g)절은 따르지 않는다.

## 0. 저장소

저장소는 사용자의 프롬프트에 적힌 것을 쓰고, 없으면 로더 skill에 적힌 것을 쓴다. 둘 다 없을 때만 어느 저장소인지 먼저 묻는다.

## 1. 목표 듣기와 기존 목표 확인

- `skills/wiki-goal/SKILL.md` (a)절대로 목표, 완료 기준, 기한·우선순위를 듣는다.
- GitHub 연결로 저장소의 `goals/` 폴더 파일 목록만 본다. 파일 이름(`<id>.toml`)이 새 목표와 겹쳐 보이는 것만 열어 제목·영역·개념을 확인한다. 위키 페이지(`wiki/`)는 열지 않는다. 폴더를 읽을 수 없으면 기존 목표를 모른다고 알리고 계속한다.

## 2. 합칠지 나눌지와 초안

`skills/wiki-goal/SKILL.md` (c)·(d)절대로 판단하고 초안을 만든다. 공식 출처는 웹에서 확인한다. 쓰기 전에 (d)절의 요약을 보여 주고 **확인을 받는다**. 확인 전에는 파일을 만들지 않는다. 기존 지도를 고칠 때 기존 개념의 `id`는 바꾸지 않는다.

## 3. 검증

**코드 실행이 켜져 있으면** 확인받은 지도를 `<스크립트 폴더>/root/goals/<id>.toml`로 쓰고 검사한다. `<스크립트 폴더>`는 로더 skill이 스크립트를 내려받은 폴더다.

```
python3 "<스크립트 폴더>/goal.py" --root "<스크립트 폴더>/root" check <id>
```

종료 코드 2이면 stderr 메시지대로 고치고 다시 검사한다. 통과하면 `start <id>`도 실행해 처음 공부할 개념(`items`)을 얻는다. 이 결과는 위키의 기존 노트를 반영하지 않는다 (모든 개념을 아직 공부하지 않은 것으로 본다).

**코드 실행이 꺼져 있거나 스크립트를 내려받지 못했으면** 아래 규칙을 직접 확인한다.
- `id`는 파일 이름과 같고, 모든 id는 `^[a-z0-9]+(-[a-z0-9]+)*$`에 맞으며 영역끼리, 개념끼리 겹치지 않는다.
- `kind`는 `official` 또는 `subjective`. 영역의 `weight`는 0보다 큰 수이고, 영역마다 개념이 하나 이상 있다.
- 개념의 `area`는 있는 영역 id다. `aliases`는 문자열 목록이다.
- 선수 관계의 `from`·`to`는 있는 개념 id이고 서로 다르며, `basis`는 `official`, `syllabus-order`, `inferred`, `user` 중 하나이고, 순환이 없다.

## 4. 커밋

`goals/<id>.toml`을 저장소의 **기본 브랜치**에 GitHub 연결로 커밋한다. 커밋 메시지는 `goal: <날짜> <id>`이다. 기존 파일을 고칠 때는 열어 본 내용에서 확인받은 부분만 바꾼다.

커밋이 실패하면(권한 없음, 연결 없음, 거절) 파일을 첨부해 내려받게 하고 이렇게 알린다. "저장소의 `goals/`에 이 파일을 넣어 주세요."

## 5. 보고

만들거나 고친 목표(id, 개념 수)와 처음 공부할 개념을 알린다. 이어서 이렇게 안내한다. "위키에 이미 있는 노트를 이 목표의 개념과 잇는 일은 Claude Code에서 `/wiki-goal <id> 노트 연결`로 합니다. 시작 개념은 `/wiki-add <개념 이름>`이나 `/wiki-learn`으로 공부하세요."
